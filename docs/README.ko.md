## 소개

lowtide는 [DeepSeek Harness (dsh)](https://github.com/deepseek-ai/dsh)용 플러그인입니다. 이 플러그인이 해결하는 문제는 단순하고 아주 자연스럽습니다:

보통 에이전트에게 작업을 시키려면 컴퓨터 앞에 앉아 지시를 보내고, 답변을 기다렸다가, 직접 검토합니다. 하지만 이런 작업 방식은 당신에게 넉넉한 여유 시간이 있다는 사실 — 그리고 일부 모델이 부과하는 피크/밸리(성수기/비수기) 요금을 피할 기회가 있다는 사실을 잊고 있습니다.

lowtide를 설치하면 하루가 이렇게 흘러갑니다: 낮에 떠오르는 작업이 있으면 큐에 넣고, 한 번 훑어보고, 승인합니다. 작업들은 당신이 정한 시간(예: 오후 7시 이후 — DeepSeek가 밸리 요금을 적용하는 시간)까지 쌓였다가 스스로 실행됩니다. 다음 날 아침 보고서를 열어보세요: 잘 된 것은 유지하고, 잘 안 된 것은 다시 보냅니다.

그게 전부입니다. 하지만 일주일만 사용해 보면 작업 리듬이 확실히 느긋해집니다 — "시간은 금이고, 효율은 생명"이라는 말을 잊지 마세요……

몇 가지 핵심 기능:

- 네 가지 실행 전략: 단일, 반복, 샘플링, 검토 — "한 번이면 충분"부터 "후보 5개를 돌려서 내가 고르겠다"까지
- 단위 테스트 168개 + e2e 스펙 10개, ubuntu / windows × node 22 / 24 환경에서 CI 그린
- 하나의 빌드 산출물이 데스크톱과 웹을 모두 지원 — 한 번 설치하면 양쪽에서 동작
- 비수기 실행이 DeepSeek의 밸리 시간대에 맞춰져 있어: 같은 배치가 피크 대비 약 절반 비용

## 에이전트와 보내는 평범한 하루는 이럴 수 있습니다…

**퇴근 10분 전.** 코드 리뷰를 마쳤으니 내일 할 작업 세 가지를 티켓으로 넣습니다: 리팩터링(반복, 3라운드), 주간 보고서(단일), 그리고 확신이 없는 디자인(샘플링, 후보 4개). 모두 승인하고 컴퓨터를 끄고 퇴근합니다. 다음 날 책상에 앉아 아침 보고서를 확인하니: 리팩터링은 끝났고, 보고서는 작성됐고, 디자인 후보 4개가 각각의 비용과 함께 나란히 놓여 있습니다.

**금요일 밤.** 일주일치 할 일을 한 번에 큐에 넣습니다: 의존성 정리, 빠진 테스트, 데이터 스크립트. 주말은 24시간 내내 밸리 요금입니다. 당신은 외출하고, 플러그인은 집에서 일합니다. 월요일에 보고서를 확인합니다 — 실패한 것은 재시도하고, 좋은 것은 병합합니다.

**오전 10시의 번뜩임.** 긴급한 버그에 대해 에이전트와 대화하던 중 "아, 문서도 업데이트해야지"라는 생각이 듭니다. 인터셉트 카드가 나타납니다: 지금 실행하면 피크 요금, 오늘 밤이면 약 절반 — 차이가 설명되어 있습니다. "비수기 큐에 넣기"를 클릭하면 초안은 그대로 보존되고, 다시 버그로 돌아갑니다.

**항상 켜져 있는 서버.** dsh를 24/7로 실행하는 머신이 있습니다. L3 완전 자동 모드로 전환한 다음 API(`POST /ds-lowtide/tasks`)를 통해 어디서든 작업을 넣습니다. 정해진 일정에 따라 실행하고 보고서를 작성합니다. 아무도 지켜보지 않지만, 샌드박스와 일일 예산, 파일 잠금은 그대로 유지됩니다.

**고객에게 보내는 작업.** 검토 전략을 사용하세요: 한 번 실행한 다음, 선택한 초점(예: "데이터 소스 오류 찾기")에 따라 결과물을 낱낱이 파헤치는 독립 세션을 자동으로 엽니다. 아침에 맨 결과물만 받는 것이 아니라 — 결과물과 비판적 검토 의견을 함께 받습니다.

**해외 거주.** 샌프란시스코에 있다면, DeepSeek의 피크 시간은 베이징 시간 기준이라 현지에서는 전날 저녁과 밤에 해당합니다. 설정에서 공식 시간을 현지 시간으로 변환해 주며, 한 번의 클릭으로 적용할 수 있습니다. 자신의 일정에 맞게 창을 설정하면, 장부는 항상 공식 요금표와 일치합니다.

## lowtide 작동 방식

```
① 투입               ② 심사               ③ 실행               ④ 수락
시간이 날 때마다:     큐 도크가 작업을      밸리 창이 열리면:     돌아와서:
인터셉트 카드에서     작업공간별로 묶고,     프리플라이트 게이트    보고서를 엽니다 —
한 번 클릭하거나, →   한 줄씩 심사:      →   5개를 통과한 후 →    결과 + diff
티켓 작성            ✓승인 ⏸연기             샌드박스에서 실행     + 실제 지출
(4가지 전략)          ✕폐기 / 전체 승인       창당 한 배치          + 절약 금액
```

작업의 생애 주기: `pending-review → queued → preflight → running → done / failed / stale / timeout`, 그리고 `deferred`(연기)와 `dropped`(소프트 삭제, 복원 가능)가 있습니다.

2단계가 lowtide를 "완전 자동화 스크립트"와 구분 짓는 핵심입니다: **모든 작업은 실행되기 전에 반드시 당신의 손으로 승인되어야 합니다** (L2에서는 창이 열리기 30분 전에 배치 전체를 한 번에 승인합니다). 기계는 스스로 실행 큐에 들어갈 수 없습니다. 실행은 자동화되어 있고, 결정은 자동화되어 있지 않습니다. 그래서 당신은 안심하고 자리를 비워도 됩니다.

## lowtide 인터페이스 둘러보기

**새 작업 모달.** 네 가지 전략이 나란히 있고, 각각 쉬운 언어로 된 힌트가 있습니다. 라운드 수, 우선순위, 실행 모드는 작업별로 함께 이동합니다 — 설정으로 돌아갈 필요가 없습니다. 작업은 "검토 대기" 상태로 들어옵니다. 어떤 것도 당신을 우회하여 큐에 들어가지 않습니다.

![new-task-modal](../assets/screenshots/new-task-modal.png)

**고급 옵션.** 모델, 추론 수준, 0~9 우선순위, 새 세션 또는 이전 세션 이어가기, 잠금 파일 목록 — 모두 하나의 작은 창에 있습니다. 잠금 파일, 간단히: 목록의 모든 항목은 실행 전에 sha256으로 검증되며, 제출한 것과 일치하지 않으면 작업은 `stale`(오래됨) 상태가 되어 실행을 거부합니다. 그렇지 않으면 큐에 넣은 파일이 대기 중에 다른 작업에 의해 덮어써질 수 있고, 이 작업이 그 위를 무작정 밟아버릴 수 있습니다.

![advanced-options](../assets/screenshots/advanced-options.png)

**모델은 자유롭게.** 배치 실행은 기본적으로 공식 `deepseek-flash`를 사용하지만, 각 작업은 자신만의 모델을 선택할 수 있습니다 — Harness에 연결된 모든 모델이 공급자별로 그룹화되어 드롭다운에 나타납니다. 프라이빗 공급자도 작동합니다. 비공식 모델은 공개 요금표가 없으므로 장부는 정직하게 "가격 미상"이라고 표시합니다. 정확한 회계를 원하면 설정에서 가격 오버라이드를 추가하세요.

![model-picker](../assets/screenshots/model-picker.png)

**창 편집기.** 다중 구간, 자정을 넘는 시간, 요일별 지정 — 모두 가능합니다. 아래에는 실시간 24시간 가격 밴드가 있습니다: 빨간색은 피크, 초록색은 밸리, 그리고 지금 당신이 어디에 있는지 표시하는 마커가 있습니다. UTC+8 밖에서는 "공식 피크 시간 적용"을 한 번 클릭하면 베이징 시간이 현지 시간으로 변환됩니다.

![window-editor](../assets/screenshots/window-editor.png)

**설정 페이지.** 창 시간, 배치당 작업 수, 작업당 최대 시간, 동시성, 일일 예산, 보고서 이력, 자율성 수준, 가격 오버라이드 — 모두 그래픽으로 처리되며 설정 파일이 없습니다. 공식 요금 규칙(새로운 주말 종일 밸리 포함)도 같은 페이지에 쉬운 말로 설명되어 있습니다.

![settings](../assets/screenshots/settings.png)

일상 흐름 속에 세 가지 화면이 더 숨어 있습니다: **가격 알약**(세션 헤더 — 바쁨/한가함, 큐 크기; 클릭하면 창 편집), **피크 시간 인터셉트 카드**(피크 시간에 입력하면 나타나고, 가격 차이가 설명되며, 초안은 보존됩니다), **실행 보고서**(아침 브리핑: 절약 금액 우선, 이상 항목 표시, 선택 대기 중인 후보, 원클릭 Markdown 복사).

## lowtide 작업공간에 대해

모든 작업은 작업공간 안에서 실행됩니다. 그 하나의 드롭다운이 세 가지를 결정합니다.

**건드릴 수 있는 파일.** 작업은 작업공간 디렉터리를 경계로 하는 샌드박스에서 실행됩니다. 잘못 고르면 기껏해야 파일을 찾지 못하고, 최악의 경우 건드리면 안 되는 것을 수정합니다.

**누구와 큐에 함께 서는지.** 같은 작업공간의 작업은 직렬로 실행됩니다(두 작업이 같은 저장소에서 다투는 일은 없습니다). 다른 작업공간은 병렬로 실행됩니다(기본 최대 3, 조정 가능). 처리량을 원하나요? 관련 없는 작업을 여러 작업공간에 분산하세요. 순서를 원하나요? 하나로 유지하세요.

**보고서가 어떻게 그룹화되는지.** 도크와 아침 보고서 모두 작업공간별로 정리됩니다 — 실제 볼륨이 생기면 이 그룹화가 유용합니다.

티켓 모달의 작업공간 드롭다운에는 세 가지 소스가 있습니다: **현재 작업공간 사용**(세션이 있는 곳 — 일반적인 경우), **목록에서 기존 작업공간 선택**(각각 절대 경로가 표시되어 어떤 프로젝트인지 항상 알 수 있음), 또는 **사용자 지정 경로…**(직접 입력). 세션 모드로 "이전 세션 이어가기"를 선택했다면 작업공간과 정확한 대화도 함께 선택하게 됩니다 — 작업은 그 대화의 맥락으로 재개됩니다.

제 조언: **프로젝트 하나, 작업공간 하나 — 섞지 마세요.** 프리플라이트의 git 스냅샷과 파일 잠금은 작업공간 범위로 한정됩니다. 한 작업공간에 여러 프로젝트를 섞는 것은 스스로를 혼란에 빠뜨리는 좋은 방법입니다.

## 네 가지 전략과 언제 무엇을 써야 하는지

| 전략 | 하는 일 | 언제 사용할까 | 비용 |
|---|---|---|---|
| **단일** | 한 번 실행, 완료 | 단순하고 명확한 작업 | 1× |
| **반복** | 한 세션에서 2–5라운드, 각 라운드가 "반복 렌즈"를 통해 이전 라운드를 개선; 두 라운드가 충분히 비슷해지면 조기 종료 | 다듬기가 필요한 작업: 글쓰기, 계획, 코드 | ~N× |
| **샘플링** | 2–5개의 독립 세션이 각각 완전한 후보를 생산하고, 비용과 함께 나란히 표시 — **당신이** 선택합니다. 기계는 미적 판단을 하지 않습니다 | 제목, 아이디어, 디자인: 정답이 아니라 선택지를 원할 때 | ~N× |
| **검토** | 실행 후 독립 세션이 "검토 초점"에 따라 결과를 낱낱이 파헤치고 소견을 작성 | 중요한 결과물, 출시 전 마지막 점검 | ~2× |

## 세 가지 자율성 수준

- **L1 작업별**: 모든 작업에 개별 ✓가 필요합니다. 초반에 쓰거나 저장소가 소중할 때 사용하세요.
- **L2 배치별** (기본값): 작업은 검토 상태로 대기하고, 배치 30분 전에 게이트 카드가 나타나 한 번에 모두 승인합니다. 승인하지 않으면 실행되지 않습니다. 일상의 기본 모드.
- **L3 완전 자동**: 제출된 작업이 즉시 큐에 들어가고 비수기에 샌드박스에서 실행되며 확인 절차가 없습니다(전환 시 두 번 확인). 항상 켜져 있는 서버용으로 설계되었습니다.

개별 작업은 티켓 모달에서 전역 수준을 오버라이드할 수 있습니다.

## 아키텍처: 당신이 없는 동안 어떻게 작동하는지

당신이 자는 동안 에이전트가 배치 작업을 실행하게 하는 것은 큰 요구입니다. 아래 네 개의 레이어가 그것을 안전하게 만듭니다.

**Cordis 마이크로커널.** dsh는 Cordis 마이크로커널 플러그인 생태계 위에서 실행됩니다: 모든 기능이 플러그인이고, 플러그인은 직접 의존성이 아니라 서비스 주입으로 통신합니다. lowtide의 호스트 반쪽은 잘 작동하는 Cordis 서비스들의 집합입니다 — 라우트, 스케줄러, 상태 머신 — 각자 맡은 일을 하고, 커널에 등록되며, harness와 함께 시작되고, 깔끔하게 제거됩니다. 쉽게 말하면: 그것은 dsh에 덧붙인 껍데기가 아니라, 커널 안에서 자란 기관입니다.

**두 얼굴, 하나의 산출물.** 호스트 반쪽(Node.js)은 스케줄링, 실행, 장부를 담당하고, 브라우저 반쪽(React)은 모든 픽셀을 담당합니다. 하나의 빌드가 둘 다를 생산합니다 — 그리고 dsh Desktop의 GUI 자체가 웹 렌더링이므로 데스크톱과 웹에 별도 브랜치가 필요 없습니다. 같은 바이트, 같은 동작.

**플랫폼 독립 코어.** `lowtide-core`는 창 모델, 가격표, 청구 공식, 큐 요약, 장부, 배치 창 계산을 담고 있습니다 — 모두 dsh API를 전혀 건드리지 않는 순수 함수이며, 자체 테스트와 함께 독립 패키지로 제공됩니다. 실질적인 이점: 코어는 순수 함수 단위 테스트 44개로 두들겨 맞았고, 만약 lowtide를 다른 에이전트 프레임워크로 포팅한다면 이 패키지는 그대로 분리해 낼 수 있습니다.

**심층 방어.** 프리플라이트 게이트 5개(작업공간이 아직 있는가, git HEAD가 움직였는가, 잠금 파일의 sha256이 일치하는가, 창에 들어맞는가, 예산이 남았는가) — 하나라도 실패하면 작업은 stale 또는 연기 상태가 됩니다. 절대 맹목적으로 실행하지 않습니다. 승인을 "never"로 설정한 세 가지 샌드박스 프리셋 — 무인 실행은 아무도 "허용"을 클릭할 사람이 없다는 뜻이므로, 허용되는 범위는 실행 시작 전에 결정됩니다. 상태 파일은 원자적으로 쓰이며, 손상되면 백업으로 자동 롤백됩니다. HTTP 라우트는 이 머신의 동일 출처 요청만 수락합니다.

상태 동기화는 SSE를 사용하며 4초 폴링으로 폴백합니다 — 큐가 움직이면 UI도 함께 움직입니다.

## 설치

**한 줄 설치 (사전 빌드):** `dsh plugin --profile web add https://github.com/KelaoHu/dsh-lowtide/releases/latest/download/dsh-lowtide.tgz` — 또는 아래에서 소스로 빌드.

사전 요구 사항: Node `^22.19 || >=24`, pnpm `11.7`. 모든 것은 공개 npm 레지스트리에 있습니다 — 프라이빗 레지스트리가 필요 없습니다.

먼저 dsh를 설치합니다(택일): DeepSeek 공식 채널의 Desktop, 또는 CLI용 `npm install -g @deepseek-ai/dsh`. 그다음 dsh 설정에서 작동하는 모델을 구성합니다(예: 공식 DeepSeek API 키) — lowtide는 당신의 자격 증명을 절대 건드리지 않습니다.

그다음 클론, 빌드, 설치:

```powershell
git clone https://github.com/KelaoHu/dsh-lowtide
cd dsh-lowtide
pnpm install

# 먼저 코어 레이어를 빌드합니다 (플러그인 테스트가 그 출력물을 참조합니다)
pnpm --filter lowtide-core bundle
# 그다음 플러그인: 호스트 반쪽 + 브라우저 반쪽을 한 번에
pnpm --filter dsh-lowtide bundle

# 프로필에 설치 — 하나의 산출물이 데스크톱과 웹을 모두 지원합니다
npx @deepseek-ai/dsh@0.1.5-rc.1 plugin --profile desktop add ./packages/dsh-lowtide   # Desktop
npx @deepseek-ai/dsh@0.1.5-rc.1 plugin --profile web add ./packages/dsh-lowtide       # Web

# 개발 인스턴스 시작 (포트 3080)
pnpm --filter dsh-lowtide dev
```

그 후 dsh를 열면: 세션 헤더에 가격 알약이 보이고 입력 영역 옆에 큐 도크가 보일 것입니다. 보이지 않으면 아래 FAQ를 확인하세요.

## 일상 사용법

**작업을 넣는 세 가지 방법.** 인터셉트 카드(피크 시간에 입력하면 한 번 클릭, 초안이 그대로 티켓이 됩니다); 티켓 모달(입력 영역 옆 "새로 만들기" — 프롬프트, 전략, 라운드, 우선순위); 또는 API(`POST /ds-lowtide/tasks`, 자신의 자동화에 연결).

**큐 도크에서의 생활.** 작업공간별로 대기 / 완료 / 폐기로 그룹화됩니다. 작업별 인라인: ✓ 승인, ⏸ 연기, ✕ 폐기(소프트 삭제, 복원 가능). "전체 승인"은 모든 것을 승인하고, "완료 정리"는 정리를 도와줍니다(장부는 영향 없음). "지금 실행"은 대기를 건너뛰고 즉시 배치를 시작합니다 — 디버깅할 때 쓰는 방법입니다.

**시간 의미.** 공식 피크 시간은 **베이징 시간** 기준으로 판정됩니다(DeepSeek가 베이징 시간으로 청구하므로 장부가 일치합니다; 주말은 하루 종일 밸리). 사용자 지정 창과 실행 창은 **현지 시간** 기준이며, 자정을 넘는 범위와 요일별 규칙을 지원합니다. 창이 끝나면 새 실행이 중지되고, 실행 중인 작업은 절대 중단되지 않습니다.

**장부.** `ledger[YYYY-MM-DD] = { yuan, savedYuan }` — 지출과 절약이 매일 누적됩니다. 표시되는 가격은 청구되는 가격입니다: 하나의 공식, 숫자 하나까지 감사 가능.

## 설정 참조

`GET /ds-lowtide/config`는 읽고, `PUT`은 부분 업데이트합니다(목록에 없는 필드는 거부됨):

| 필드 | 타입 | 기본값 | 설명 |
|---|---|---|---|
| `autonomy` | `'l1'\|'l2'\|'l3'` | `l2` | 자율성 수준; 티켓 모달에서 작업별 오버라이드 |
| `batch.window` | `"HH:MM-HH:MM"` | `19:00-23:30` | 밸리 실행 창(로컬 시간대) |
| `batch.windows` | `"HH:MM-HH:MM"`[] | — | 여러 실행 창(1–6개); 각 창은 하루에 한 번 배치를 실행합니다. 없으면 단일 `batch.window` |
| `batch.tz` | IANA 시간대 | 시스템 | 실행 창 시간대(비우면 로컬) |
| `batch.gateLeadMin` | 분 | `30` | 배치 게이트 사전 시간 |
| `batch.maxTasksPerNight` | 숫자 | `10` | 배치당 작업 수 상한 |
| `batch.maxDurationMin` | 분 | `240` | 작업당 최대 시간(시간 초과 시 취소 + 1회 재시도) |
| `batch.maxConcurrency` | 숫자 | `3` | 최대 동시성 1–8(작업공간 내 직렬, 작업공간 간 병렬) |
| `batch.paused` | 불리언 | `false` | 자동 배치 일시 중지 |
| `budgetDailyYuan` | ¥ | `0` | 일일 예산(0 = 무제한) |
| `windows[]` | 배열 | `[]` | 사용자 지정 창; 비우면 공식 피크(베이징 시간) |
| `windows[].level` | `peak\|off\|custom` | — | 피크 / 밸리 / 사용자 지정(밸리 가격 × 배율) |
| `windows[].start/end` | `"HH:MM"` | — | 로컬 시계, 자정 넘김 지원 |
| `windows[].days` | `1..7` 배열 | 매일 | ISO 요일(1 = 월 … 7 = 일) |
| `windows[].tz` | IANA 시간대 | 시스템 | 창별 시간대 |
| `windows[].multiplier` | 숫자 | `1` | 사용자 지정 창의 밸리 가격 배율 |
| `prices[model].{peak,off}.{input,inputCached,output}` | ¥/1M | 공식 | 가격표 오버라이드 |

## HTTP API

접두사 `/ds-lowtide/`, 동일 출처 + 루프백 신뢰 경계 뒤에 있습니다:

| 메서드 | 경로 | 용도 |
|---|---|---|
| GET | `/state` | 통합 상태(가격/카운트다운/큐/최신 보고서) |
| GET | `/events` | SSE 증분 푸시(클라이언트는 4초 폴링으로 폴백) |
| GET/PUT | `/config` | 설정 읽기/쓰기 |
| POST | `/tasks` | 티켓 제출 |
| POST | `/tasks/:id/approve \| defer \| drop \| cancel \| retry \| restore \| delete \| choose-candidate` | 심사 및 관리 |
| POST | `/tasks/approve-all` | 전체 승인 |
| POST | `/estimate` | 견적: 피크 vs 밸리 |
| POST | `/batch/run-now` | 지금 배치 실행 |
| POST | `/dismiss` | 오늘 남은 시간 동안 인터셉트 안 함 |
| GET | `/health` | 하트비트 |

## 권한 프리셋

| preset | sandbox | approval |
|---|---|---|
| `lt-readonly` | read-only | never |
| `lt-standard` | workspace-write | never |
| `lt-trusted` | danger-full-access | never |

투입 UI는 선택을 제공하지 않습니다 — 모든 작업은 `lt-standard`로 실행됩니다. 나머지 두 개는 API 호출자(`POST /tasks`의 `permissionPreset`)를 위해 남아 있습니다. 프리플라이트 없이는 아무것도 실행되지 않습니다.

## 데이터와 상태

- 모든 것이 `$DSH_HOME/lowtide.json`에 저장됩니다(원자적 쓰기, 손상 시 자동 롤백). `DSH_PROFILE`이 설정되면 상태는 프로필별로 격리됩니다. **파일당 한 번에 한 작성자** — 프로필 격리 없이 Desktop과 Web을 동시에 실행하지 마세요.
- 창당 한 배치, 자정을 넘겨도 안전; 빈 큐는 빈 보고서를 만들지 않습니다.
- 연기 복구: 창이 열리면 프리플라이트로 연기된 작업이 자동으로 다시 큐에 들어갑니다(≥3회 실패 시 실패 처리); 수동으로 연기한 작업은 검토 대기로 돌아갑니다.

## 테스트와 CI

```powershell
pnpm --filter lowtide-core test    # 순수 함수 코어 테스트 44개
pnpm --filter dsh-lowtide test     # 플러그인 단위 테스트 124개
pnpm --filter dsh-lowtide exec playwright test   # e2e (:3080에서 dsh web 실행 필요)
```

10개의 e2e 스펙은 직렬로 실행되며, 양면 로드 스모크부터 실제 API에 대한 투입→심사→실행→보고서 전체 루프까지 다룹니다. 저장소에 GitHub Actions 워크플로가 포함되어 있습니다: 모든 push / PR에서 install → build → typecheck → 전체 단위 테스트 스위트를 네 가지 환경에서 실행합니다.

## 보안

- 라우트는 루프백 + 동일 출처만 허용합니다. **포트 3080을 공개 인터넷에 노출하지 마세요** — SSH 터널 또는 인증된 리버스 프록시를 사용하세요.
- Windows 샌드박스는 완화 수준입니다. Linux/macOS는 완전히 강제합니다. 무인 사용에는 파일 화이트리스트와 일일 예산을 함께 쌓아두세요.
- L3 완전 자동으로 전환할 때는 두 번 확인합니다.
- 상태 파일에는 전체 작업 프롬프트와 경로가 포함됩니다. 백업도 그에 맞게 취급하세요.
- 취약점은 [SECURITY.md](../SECURITY.md)를 통해 비공개로 신고하세요.

## FAQ

**창이 왔는데 아무것도 실행되지 않았나요?**
순서대로 확인하세요: 작업이 승인되었는가? → "밸리 배치 일시 중지"가 체크되어 있는가? → 게이트가 승인되었는가? → 예산이 소진되었는가? → 프리플라이트가 실패했는가(작업이 `stale`이 되며, 상세 보기에 이유가 표시됨)?

**샘플링이 왜 자동으로 최고 후보를 고르지 않나요?**
의도된 설계입니다. 기계는 미적 판단을 하지 않습니다 — 후보와 비용이 나란히 놓이고, 당신이 "이것으로 선택"을 클릭합니다.

**해외에 있는데 피크 시간이 내 일정과 맞지 않나요?**
설정에서 공식 시간이 현지에서 어떻게 보이는지 표시합니다. 자신의 리듬에 맞게 사용자 지정 창을 설정하거나, "공식 피크 시간 적용(내 시간대로 변환)"을 클릭하세요.

**견적과 실제 지출이 맞지 않나요?**
견적은 대략적인 입력 토큰 상한을 사용합니다. 실제 지출은 실제 사용량(출력과 캐시 히트 포함)을 사용합니다. 두 숫자 모두 보고서에 있습니다.

**작업이 stale이 되었나요?**
프리플라이트 실패입니다: 작업공간이 사라졌거나, git 스냅샷이 움직였거나, 잠금 파일이 변경되었거나, 예산이 부족하거나, 창에 들어맞지 않습니다. 상세에서 `lastError`를 읽고, 고친 후 `retry`하세요.

## 알려진 제한 사항과 로드맵

- 릴리스 후보(v0.2.2), 소스에서 설치됨; e2e는 실행 중인 dsh web 인스턴스가 필요합니다.
- 기본 배치 모델은 `deepseek-flash`입니다. 비공식 모델은 공개 가격표가 없어 장부에 "가격 미상"으로 표시되며, 설정에서 채울 수 있습니다.
- 작업당 상한은 240분이며, 시간 초과 시 취소 후 한 번 재시도합니다.
- 로드맵 후보: 다중 창 다중 배치, 작업 의존성 그래프, 예산 자동 분배, 보고서 푸시(이메일/Webhook), 가격 변동 알림.
